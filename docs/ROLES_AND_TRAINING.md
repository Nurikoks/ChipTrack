# ChipTRick: роли, проверка разметки и обучение

Описание фактической реализации на 18.10.2026.

## Что делает «Обучить кандидата»

Кнопка доступна только администратору. Она запускает отдельный процесс Python; действующая модель продолжает обслуживать видео.

1. Собирается набор: исходные размеченные видео с подготовленными признаками плюс исправления пользователей, для которых есть разрешение владельца на обучение и одобрение администратора. Неполный анализ, несовместимые признаки и конфликтующие исправления одинакового видео исключаются. Дубликаты считаются по хешу содержимого.
2. Проверяется минимум: четыре уникальных подходящих видео, среди них нормальные и нарушения. Второе одновременное обучение не запускается.
3. Сохраняется снимок набора и его хеш. Последний набор содержал 40 уникальных видео, 343 временных окна, 70 числовых признаков и 13 категорий событий.
4. На CPU обучается небольшой классификатор: веса для признаков каждого типа события. 180 эпох — 180 проходов обновления весов. Детектор RT-DETR, Qwen3-VL и MediaPipe не переобучаются. На таком небольшом наборе сама оптимизация может занять меньше секунды: это нормально. Извлечение визуальных признаков при анализе видео значительно дольше.
5. Проверка проводится по четырём группам целых видео: обучить на трёх группах, проверить на четвёртой, повторить. Фрагменты одного видео не пересекаются между обучением и проверкой. Однако исходные правила уже разрабатывались на этих роликах — это оценка разработки, не независимый тест всей системы.
6. Создаются файлы `classifier.json`, `dataset.json`, `report.json` в `runtime/models/<run_id>`, новая запись `candidate-...`, логи эпох/loss и сравнение с действующей версией.
7. При увеличении пропусков, ложных событий/тревог или просмотров, уменьшении правильных событий либо отсутствии улучшения выпуск блокируется.
8. Если проверка пройдена, администратор смотрит отчёт, примеры и нажимает «Выпустить версию». Только тогда новые анализы используют кандидата. Старые результаты сохраняют свою версию и не пересчитываются; уже начатый анализ завершает работу со своей версией.

Нажатие кнопки **само по себе не переключает рабочую модель**. Повторное обучение без новых примеров и изменения алгоритма обычно даёт те же веса/качество, хотя идентификатор кандидата будет новым. Снижение loss не доказывает улучшение на новых видео.

Есть автоматический запуск: фоновая проверка раз в минуту запускает кандидата после накопления минимум пяти новых уникальных пригодных подтверждённых исправлений. Выпуск остаётся ручным. Сейчас последний кандидат отклонён, активна `rules-2.0-acd1be0e`.

## Что такое «Проверка разметки»

Это рабочее место администратора для проверки человеческих исправлений. Оно не создаёт модель и не является повторным анализом видео.

Пример: модель сообщила «нарушений нет»; пользователь один раз указал «ключ оставлен в сейфе, 12–15 секунд» и сохранил пояснение. Исправление появится здесь вместе с видео, типом, интервалом и состоянием разрешения на обучение.

- «Подтвердить разметку»: администратор просмотрел пример и считает исправление пригодным для обучения.
- «Отклонить разметку»: исправление остаётся в истории, но не используется как подтверждённый обучающий пример.
- Одобрения недостаточно: переключатель владельца «Использовать для обучения» также должен быть включён.
- Администратор может пересмотреть решение об одобрении/отклонении. Это не меняет саму однократную запись пользователя.
- Исходный ответ модели сохраняется. Отказ администратора не удаляет исправление из личной истории и не открывает пользователю повторное редактирование.
- Отзыв согласия/одобрения исключает пример из следующего обучения и блокирует выпуск ещё не выпущенного кандидата, обученного на нём. Уже действующие веса автоматически не забывают этот пример.
- Простая загрузка видео и включение переключателя без проверенного исправления не добавляют его в набор обратной связи. Исходный размеченный набор используется отдельно.

Администратор видит исправления даже при выключенном разрешении на обучение: он проверяющий, которому показываются эти обращения. Отдельной роли «разметчик» пока нет.

## Роли и экраны

| Возможность | Обычный пользователь (`user`) | Администратор (`admin`) |
|---|---|---|
| Регистрация через сайт | Создаёт только обычную роль | Администратора создаёт оператор локально |
| Обзор, загрузка, личная история, просмотр видео | Да, свои данные | Да, свои данные |
| Одно исправление и разрешение обучения | Для своего видео | Для своего видео; дополнительно для загрузок API |
| Чужая личная история целиком | Нет | Нет отдельного общего списка; доступны видео из исправлений и набора оценки |
| «Видео API» | Нет | Да, загрузки по общему ключу жюри |
| «Проверка разметки» | Нет | Все присланные исправления, видео и решение об одобрении |
| «Модель и обучение» | Нет | Кандидаты, отчёты, запуск, выпуск и возврат совместимой версии |
| «Журналы» | Нет | Анализ, обучение, версии, общий поток |

Обычный пользователь видит «Обзор» и «Мои видео», индикатор готовности/версию и выход. Администратор дополнительно видит «Видео API», «Модель и обучение», «Проверка разметки», «Журналы». Ограничения проверяются сервером, а не только скрытием кнопок.

Гость может открыть страницу входа и зарегистрироваться. Без входа нельзя получить историю или видео. Технический аккаунт `jury-api` используется для API-загрузок; войти им через форму нельзя. Ключ API даёт загрузку/получение результатов API, но не права администратора. Для всех владельцев одного ключа API используется общая история API; это не отдельный пользовательский кабинет каждого члена жюри.

## Конкурсное ограничение

Полученный кейс запрещает обучение на скрытых видео жюри. Текущая возможность opt-in для API была реализована по раннему пожеланию пользователя; она не отменяет это требование. Пока это расхождение не урегулировано, не включайте тестовые видео жюри в обучение. Проверка публичного адреса 18.10.2026 выполнена исключительно на искусственном ролике, без банковских записей.
