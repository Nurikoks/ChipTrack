# Демонстрация ChipTRick

Откройте `Start-ChipTRick.cmd`, затем http://127.0.0.1:8000.
Данные локального администратора создаются при первом запуске в `runtime/admin-login.txt`.
Ключ API хранится в `runtime/api-key.txt`. Он не выводится в журналы. По прямому уточнению пользователя реализована возможность разрешить обучение на загрузках API: администратор размечает их в разделе «Видео API», затем подтверждает разметку в разделе «Проверка разметки».
**Расхождение с полученным кейсом:** раздел 10 файла «Кейс_ForteBank.docx» прямо запрещает обучение на тестовых видео жюри. Техническая возможность и пользовательское разрешение не подтверждают соответствие конкурсу. До отдельного уточнения организаторов тестовые видео жюри не следует включать в обучение; для конкурсного запуска нужен запрет на уровне сервера. Текущий переключатель по умолчанию выключен. При проверке 18.10.2026 использованы только исходные обучающие ролики.
После включения видео в обучающий набор оценка на этом видео не считается независимым тестом. Источник `jury_feedback` сохраняется в снимке данных.
У каждой новой загрузки есть переключатель «Использовать это видео для обучения», по умолчанию выключенный. Для отбора нужны одновременно разрешение и одобренная разметка. Выключение исключает пример из следующих обучений; уже выпущенные веса автоматически не переучиваются.
Обычные пользователи регистрируются на сайте. Администратор проверяет исправления и выпускает версии.

## Три независимых потока

Откройте `Logs-Inference.cmd`, `Logs-Training.cmd`, `Logs-Versions.cmd` в отдельных вкладках терминала.
`Jury-Three-Tabs.cmd` открывает сразу три вкладки, если установлен Windows Terminal.
`Logs-All.cmd` показывает общий хронологический поток. Все записи сохраняются в `runtime/logs/`.
Запись эпохи означает выполненный шаг оптимизации. Если обучения нет, журнал обучения не имитирует активность.

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m app.cli status
.\.venv\Scripts\python.exe -m app.cli versions
.\.venv\Scripts\python.exe -m app.cli changes
.\.venv\Scripts\python.exe -m app.cli logs inference --follow
.\.venv\Scripts\python.exe -m app.cli logs training --follow
.\.venv\Scripts\python.exe -m app.cli logs versions --follow
.\.venv\Scripts\python.exe -m app.cli logs all --follow
.\.venv\Scripts\python.exe -m app.cli train
.\.venv\Scripts\python.exe -m app.cli report
```

`train` создаёт реального кандидата, если подготовлен набор признаков. Обучение небольшой модели на CPU может закончиться быстро — это нормальное поведение, журналы остаются доступны.

Выпуск доступен администратору в разделе «Модель» и оператору CLI:

```powershell
.\.venv\Scripts\python.exe -m app.cli release candidate-ID --reason "Проверены ошибки в отчёте"
.\.venv\Scripts\python.exe -m app.cli rollback rules-2.0-HASH --reason "Возврат к проверенной версии"
```

В командах замените `candidate-ID` и `rules-2.0-HASH` на реальные идентификаторы из `versions`.
У кандидата должны пройти условия качества. Отчёт разработки не является независимой оценкой на неизвестной камере.
Для каждого анализа сохраняется версия. Выпуск меняет версию для новых заданий; уже выполняемый анализ завершает работу со своей версией.

## Проверка проекта

```powershell
$env:HF_HOME = "$PWD\hf"
.\.venv\Scripts\python.exe -m app.cli evaluate
.\.venv\Scripts\python.exe -m pytest tests -q
```

Полный прогон записывает `runtime/reports/current/results.jsonl`, `metrics.json`, отчёт по каждому видео и `runtime/dataset/seed.jsonl`.
API сохраняет статусы `processing/done/failed` из задания. Если интерфейс показывает «Требует просмотра» без подтверждённых нарушений, API возвращает `failed` с причиной `insufficient_evidence`. Это считается необработанным видео, а не успешным чистым вердиктом; в оценке такие случаи не исключаются из знаменателя recall.
Исторические метрики в `docs/evaluation.md` относятся к исходному проекту и не подтверждают качество новой версии.
