# ForteBank Datathon 26 — локальный AI-сервис проверки кассовой дисциплины по видео

Сервис принимает видеозапись кассового рабочего места (вид сверху) и сообщает проверяющему:
есть ли визуальные признаки возможного нарушения, **когда** (таймкод), **что видно** (кадры-доказательства
и описание) и **какое правило** может быть затронуто (документ НБРК/АРРФР, пункт, ссылка на adilet.zan.kz).
Результат — подсказка для человека, а не юридическое заключение.

* Всё выполняется **локально** (рассчитано на RTX 3050 4 ГБ, сдаваемый сервис работает на RTX 4060 Laptop 8 ГБ): детектор RT-DETRv2 + VLM Qwen3-VL (Apache-2.0). Без облачных API;
  после загрузки весов интернет не нужен (`HF_HUB_OFFLINE=1`).
* Анализ только визуальный, без звука и без распознавания лиц: люди различаются только по позиции и поведению.
* Сервер видео не сохраняет: файл удаляется сразу после обработки, результаты хранятся в памяти 6 ч.
  Веб-интерфейс ведёт историю проверок в браузере проверяющего (IndexedDB): видео, вердикт и кадры-доказательства
  остаются на этом устройстве, пока проверяющий не удалит проверку или не нажмёт «Очистить историю». На сервер история не передаётся.

## 1. Запуск (Windows, нативно)

```powershell
# 1) окружение (вне OneDrive, на диске с местом)
python -m venv E:\fortebank_env
E:\fortebank_env\Scripts\python.exe -m pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
E:\fortebank_env\Scripts\python.exe -m pip install -r requirements.txt

# 2) веса (один раз, нужен интернет)
$env:HF_HOME="E:\fortebank_env\hf"; E:\fortebank_env\Scripts\python.exe scripts\download_weights.py

# 3) сервис (офлайн); при первом запуске генерируется и печатается API-ключ (runtime\api_key.txt)
powershell -ExecutionPolicy Bypass -File scripts\start_service.ps1 -Port 8000
```

Скрипты по умолчанию ищут окружение в `E:\fortebank_env`. Если оно в другом месте, перед запуском задайте
`$env:FORTE_PYTHON = '<окружение>\Scripts\python.exe'` и `$env:HF_HOME = '<окружение>\hf'`.

Интерфейс: `http://localhost:8000/` · проверка: `GET /health` (HTTP 200 и `"status": "ok"`; HTTP 503 и `"status": "degraded"`, если GPU-воркер остановился или завис).

Параметры `start_service.ps1`: `-Port` (по умолчанию 8000); `-BindHost` (по умолчанию `127.0.0.1`: сервис доступен только с этой машины, `-BindHost 0.0.0.0` открывает его в локальную сеть — для ngrok это не нужно); `-Tunnel` (Cloudflare, см. ниже). Ключ читается из `runtime\api_key.txt` или из `FORTE_API_KEY`; пробелы по краям обрезаются, ключ должен быть ASCII.

Linux + Docker (NVIDIA Container Toolkit): веса скачать в `./models` (`HF_HOME=./models python scripts/download_weights.py`),
затем `FORTE_API_KEY=<ключ> docker compose up -d`. *Docker-образ подготовлен, но на машине команды не проверялся (нет Docker).*

### Публичный URL
Используется ngrok (бесплатный аккаунт команды; установка: `winget install ngrok.ngrok`):
```powershell
ngrok update                                                  # агенту нужна версия ≥ 3.20 (winget ставит старую)
ngrok config add-authtoken <токен из dashboard.ngrok.com>     # один раз
ngrok http 127.0.0.1:8000                                     # публичный https-адрес (статический домен аккаунта)
```
Именно `127.0.0.1:8000`, а не `8000`: ngrok разрешает `localhost` в IPv6 `[::1]`, а сервис слушает только IPv4,
и туннель отвечает `502 ERR_NGROK_8012`. Бесплатный ngrok сам выдаёт аккаунту один статический домен, поэтому адрес
не меняется при перезапуске туннеля. Браузер при первом
заходе показывает страницу-предупреждение ngrok (кнопка «Visit Site»); запросы к API через curl она не затрагивает.
Важно про приватность: ngrok пересылает HTTP-запросы через свою инфраструктуру, поэтому загружаемое видео проходит через edge-серверы ngrok по TLS; это не сквозное соединение до этой машины. Обработка видео и все модели остаются на этой машине, файл удаляется сразу после обработки.
Cloudflare quick tunnel (`scripts\start_service.ps1 -Tunnel`) в нашей сети заблокирован (порт 7844 сбрасывается),
поэтому выбран ngrok (работает через 443). Известная особенность ngrok: если файл больше ~1 МБ отправлен **без** верного ключа, curl посылает
`Expect: 100-continue`, и через туннель ответ приходит со статусом `200` вместо `401`, но с телом
`{"detail": "invalid or missing X-API-Key"}` и без `job_id` (локально сервис отвечает `401`). С маленьким телом,
без `Expect` (`-H "Expect:"`) и с верным ключом всё штатно.

### Переменные окружения
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `FORTE_API_KEY` | — (обязательна) | ключ для заголовка `X-API-Key` (ASCII, пробелы по краям обрезаются) |
| `FORTE_VLM` | `Qwen/Qwen3-VL-2B-Instruct` | VLM (альтернатива `Qwen/Qwen3-VL-4B-Instruct`) |
| `FORTE_JOB_DEADLINE_SEC` | 270 | жёсткий лимит на задачу, отсчёт от начала HTTP-запроса загрузки (время загрузки входит); декодирование останавливается по нему; по истечении — лучший частичный результат (`partial: true`) |
| `FORTE_MAX_UPLOAD_MB` | 300 | максимальный размер файла; больший файл отклоняется с `413` до приёма тела запроса |
| `HF_HOME` | — | каталог с весами |
| `FORTE_DEBUG` | 0 | добавить в ответ отладочный блок (для разработки) |
| `FORTE_EXPERIMENTAL` | 1 | проверка T09 (приём сумки у инкассатора без документа); `0` — выключить |

## 2. API (для жюри)

```bash
curl -X POST https://<host>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
# -> {"job_id": "3f2a9c1e0b7d4a8c9e1f2a3b4c5d6e7f"}
curl https://<host>/api/v1/jobs/3f2a9c1e0b7d4a8c9e1f2a3b4c5d6e7f -H "X-API-Key: <ключ>"
```

Ответ по готовности (обязательные поля — строго по ТЗ; дополнительные поля только добавлены):
```json
{
  "job_id": "3f2a9c1e0b7d4a8c9e1f2a3b4c5d6e7f", "status": "done", "verdict": "violation",
  "violations": [{
    "type": "Ценности/документы оставлены без присмотра на рабочем месте",
    "timecode_sec": 9.0,
    "description": "На видео работник отходит от рабочего места, на столе остаются банкноты; ... Правило: ...",
    "evidence_frames": [{"timestamp_sec": 9.0, "image_base64": "/9j/..."}],
    "type_id": "T01_UNATTENDED_VALUABLES", "confidence": 0.99,
    "rule": {"grounding": "medium", "references": [{"document": "...", "clause": "п. 20, ч. 2", "url": "https://adilet.zan.kz/rus/docs/V1900019680", "verified": true}]}
  }],
  "partial": false, "warnings": [], "video_duration_sec": 19.8, "processing_time_sec": 24.1
}
```
* `status`: `processing` → `done` | `failed`. Каждая задача обязательно завершается; повреждённый/неподдерживаемый файл → `failed` с сообщением.
* Без ключа или с неверным ключом → `401`. Неподдерживаемое расширение или содержимое, не похожее на видео (проверяется сигнатура контейнера) → `415`; пустой файл → `400`; больше лимита → `413` (решается по `Content-Length` до приёма файла). Видео разрешением выше 4K (4096×2304) → `failed`. Ошибка валидации запроса → `422`, `detail` — строка.
* Задачи обрабатываются очередью на одном GPU; несколько одновременных загрузок допустимы. Задачи жюри (с ключом) выполняются раньше задач веб-интерфейса.
* `partial` и `warnings`: `partial: true` значит, что результат может быть неполным: проверки пропущены или обрезаны по сроку, проверка завершилась ошибкой, видео обрезано при декодировании, достигнут лимит кадров, не найдены стол или люди, либо модель вернула нечисловой ответ. `warnings` — список причин (например, `check_skipped:periodic`, `anchor_missing:safe`). Информационные предупреждения (нет сейфа, ноутбука или двери в кадре; `report_degraded:<тип>`) `partial` не выставляют. Поэтому `verdict: "no_violation"` при `partial: true` означает «не подтверждено», а не «нарушений нет»; веб-интерфейс показывает такой результат с предупреждением.
* Веб-интерфейс: `/ui/analyze` возвращает `429`, пока в очереди веб-интерфейса 3 задачи (загрузки, которые ещё передаются, тоже считаются). `/ui/jobs/{id}` не отдаёт задачи жюри (`404`), потому что результаты жюри содержат кадры с людьми и требуют ключа.
* Ошибки обработки в `error` короткие: `processing failed (<тип исключения>)`; ошибки декодирования сохраняют своё сообщение. Если задача не завершилась через 20 с после срока, она получает `failed` с сообщением `processing did not finish in time`. Задача, у которой к началу анализа до срока осталось меньше 30 с (долгая загрузка или длинная очередь), сразу получает `failed` с сообщением `job waited in queue past its deadline`: за это время успевают только декодирование, детекция и привязка сцены, и результат был бы пустым «неполным» ответом.

## 3. Ограничения
См. раздел «Ограничения и известные ошибки» в [docs/architecture.md](docs/architecture.md) и результаты оценки в
[docs/evaluation.md](docs/evaluation.md).

Качество на 40 обучающих клипах (in-sample: пороги подобраны на тех же клипах, цифры оптимистичны): v8 находит нарушение в 18 из 21 видео с нарушениями, но даёт ложное срабатывание на 9 из 19 видео без нарушений (precision 0.67). Выбран режим «лучше лишний просмотр, чем пропуск»: проверяющий смотрит каждое предупреждение. Работа на новом ракурсе камеры пока не оценена.
